# 上游功能不回退：产品验收基线

2026-11-07 用户明确要求：最终功能不能少于上游，包括视频指定片段下载；第三方 API
也可以参考。这项要求覆盖旧文档中把媒体、分享等列为可无限延期的理解。阶段预览仍可交付，
但不能称为完整客户端或上游对齐版。

## 比较范围与证据

主基线为 Piko v1.4.0，commit `d61c1580783911be557d4c39026c300517187bcb` 的已发布
Windows x64 用户行为。pikpaktui、pikpak-kotlin、Rclone 和官方 CLI 是补充能力/协议参考，
不是必须一并嵌入的运行时。Bern 是界面框架参考，不是云盘功能基线。
详见 [上游研究](UPSTREAM_PARITY_RESEARCH.md) 和 `parity-manifest.json`。

固定版本用于可重复验收，不是永久停在旧版：每个正式发布候选重新审计上游最新稳定版本，
记录新增项，不能用旧基线悄悄避开新增功能。Android、Windows ARM64、macOS、Linux
另有平台条目，当前 Windows x64 优先；不能宣称跨平台已对齐。

第三方/社区接口允许研究与独立实现。每个适配器按真实能力协商，可用合适的兼容 API
补足 CLI 不支持的媒体、分享、配额、随机读取；不把 CLI 功能当产品上限。来源许可证、
账号授权、接口变动、错误语义和日志保护仍逐项核验，不复制他人凭据或绕过账号控制。

## 必须闭环的能力

- 文件：目录树、完整分页、搜索/模糊筛选、路径定位、排序记忆、大目录、多标签/快速访问。
- 整理：目录/移动/复制/回收站/恢复/星标、批量重命名和预览/撤销、跨目录重复文件检查。
- 传输：整文件和目录、上传、云任务、原画/转码选择、限速、可靠恢复、配额、错误和校验。
- 视频：播放/seek/轨道/字幕、片段选择与下载、信息流、图库、外部播放器。
- 片段：本地与远端、MP4/MKV/TS、前关键帧对齐、音视频同步、fast-start MP4、明确轨道损失，
  取消/恢复/旧目标保护、远端随机读取/缓存，而非默认整片下载后裁剪。
- 分享/归档：链接解析与预览、选择转存/直接下载/引用，归档与取回，压缩包浏览/选择解压。
- 本地/账号/体验：本地目录只读映射、跨账号隔离、语言、辅助功能、更新、托盘。
- NekoPak 自有目标：安全单向/双向文件同步、Cloud Files、可选 WinFsp/FUSE，分别验收。

## 发布门禁

`python scripts/check_parity.py` 校验清单格式并报告差距；
`python scripts/check_parity.py --release` 是正式 Windows 功能对齐版的门禁。
打包可用 `python scripts/package_release.py --parity-release` 强制先过门禁；
CI 的 `parity-*` 标签同样执行严格门禁，默认开发预览不会冒充对齐版。

所有 mandatory_windows 项均需 `verified`、真实验证证据路径和验收说明。
正式候选还必须在清单中提供 release_review（release_candidate、baseline_commit、reviewer、
reviewed_at、evidence）；复核记录需在7天内且指向存在的最新稳定版审计文件。脚本验证
结构/时效/证据存在性，证据真实性和完整功能行为仍需人工审阅，不能把布尔值当实测。
`partial`、`planned`、`blocked`、`unverified` 都不能通过正式门禁，Mock 不计为真实实现。
新增/删除/降级清单项须说明来源或用户明确的范围变更。P0/P1/P2 只表示顺序；体积、
缺少一个后端或允许可选依赖都不能成为自动删除能力的理由。外部组件缺失时禁用功能
是安全行为，但不等于该功能已经通过对齐验收。

Lite 保持小包，不捆绑全部媒体/驱动/CLI；按需媒体组件、系统组件或另行安装的工具可以
实现完整功能，但必须有可操作的安装/发现/验证流程，说明总占用并通过同一验收。

## 当前最高优先级差距

视频选段先落独立 Rust 媒体核心，本轮只实现本地 MP4/MKV 流复制实验路径。
TS 回前一关键帧的实际测试失败，已拒绝 TS 输入并保持门禁未通过；远端 Range/缓存、
画质选择、轨道完整性、任务恢复、播放器入口和真实账号测试仍必须补齐。
不能把“本地导出成功”宣传为“云端片段下载完成”。

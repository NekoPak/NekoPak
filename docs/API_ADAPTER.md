## 运行与配置

默认桌面只注册 `rust_compat`。`NEKOPAK_BACKEND=mock` 是显式离线开发模式，
只注册 mock；任何其他值（包括旧的 official_cli）启动失败。程序不读取旧 CLI 路径，
不搜索 PATH，不启动 PikPak 外部可执行文件，不自动下载依赖，也没有备用 CLI 连接。
`official_cli` 枚举仅为读取历史数据保留；旧 CLI 数据库不会删除、迁移或当作 Mock 使用。

生产端点固定为 `https://user.mypikpak.com` 和 `https://api-drive.mypikpak.com`。
前端 CSP 只放行本地 IPC；所有远端请求由 Rust 发起。HTTPS 证书校验保持启用，禁止
自动跟随重定向；不接受来自 UI/配置的任意 API 主机。HTTP 测试服务器仅在测试编译中启用。

默认内置官网公开 Web 登录 client ID 与 SDK 协议版本，普通用户无需配置环境变量，
可直接输入邮箱和密码发起登录。公开标识不是账户凭据，不包含 client_secret、
Android 身份或验证码解题逻辑。开发者显式覆盖参数仅用于协议调试，不是使用前提。
官网脚本来源、SHA-256 和请求差异见 `NATIVE_LOGIN_RESEARCH.md`。

## 已实现、已离线验证的范围

- 邮箱+密码 → captcha init → signin；密码不存入 Session/SQLite/配置/事件。
  窗口输入在任何请求结果后清除；Rust 接收的密码与会话秘密使用 zeroize 清除。
  不宣称能够清除 WebView/HTTP 库中所有临时内存副本。
- 人工 CAPTCHA 返回限定 PikPak HTTPS 域名的验证链接；不会自动解题或绕过。
  等待期间只保存短期 challenge ID、账号与设备元数据，五分钟过期；继续登录时重新
  输入密码并使用回调收到的新 CAPTCHA token 发起 signin，不凭“已完成”按钮跳过校验。
  仅监听随机回环端口/路径，校验 state，过期或退出即关闭；真实人工验证由用户实测。
- 设备 ID 是本客户端随机 UUID，存于本机凭据项；不从账号推导、不冒充 Android。
- Windows Credential Manager：调用系统 CredReadW/CredWriteW/CredDeleteW，按数据目录
  和客户端 ID 隔离凭据名称。token 与过期时间只存系统库；其他 OS 暂不提供明文降级。
- 恢复和刷新：串行刷新；并发 401 共享更新后的 token；仅重放一次只读 GET。
  invalid_grant 或刷新后仍 401 使会话过期并删除 token。临时网络失败保留可恢复会话。
  退出会让进行中的目录读取作废，旧响应不能写进新账号界面。
- 会话状态读取失败时提供重试连接与清除本地会话，凭据库不可用时禁用密码输入。
  退出/过期会清空账号相关 UI 缓存、剪贴板、撤销和面板；主题/密度保留。
  因尚无稳定账号范围的偏好契约，桌面固定目录目前只保留在当前会话，启动时清除旧记录。
- 目录与 stat：根目录映射、严格十进制 u64、UTC 时间、父目录校验、分页游标按
  会话/目录/limit 隔离；重复游标、循环、过期游标、超量页面均失败，不当空目录。
  未标明算法的 gcid 不冒充 MD5/SHA1。只白名单文件字段跨 IPC，丢弃下载直链/medias。
- 每个 HTTP 请求超时，响应最大 4 MiB；按 200ms 间隔获得请求时隙。仅连接建立失败、
  HTTP 正文尚未发送时做最多四次连接尝试；HTTP 错误或正文传输失败不自动重放。
  429 显示 Retry-After，不自动换后端。错误文本不引用上游原始诊断，可复制脱敏信息。
- Windows 使用系统 TLS 与 HTTP/1.1 兼容配置，保留证书链、域名校验及 TLS 1.2 下限；
  跟随已有系统代理，不修改 Hosts/DNS/代理等 OS 设置。本机认证域名曾返回连接重置，
  成功握手也有观察，不能据此声称稳定连通或已成功登录。详见登录修复报告。

## 尚未实现 / 未验证

真实 Free/Premium 登录、实际人工 CAPTCHA 返回路径、会员信息、
配额、写操作和持久远端幂等意图、实际下载/Range/缓存/恢复、分享、上传、媒体、同步、
挂载均未完成服务验收；手机号/短信/邮箱验证码接口不启用。
没有把 `user/me` 或会员结果伪造成已查询，当前 account_tier 保持 unknown。

文件 list/stat 仅在已获得会话时声明 ready，始终标为协议预览，不能由此宣称生产稳定。
配额能力为 false，缺少数据时不可推算；客户端协议的额度规则也不能直接套用 Connected Apps。
本轮不执行任何真实账户的写入、下载或授权操作。

v3 的片段、画质、分享、解压等界面已经合入，但桌面按 Rust 能力禁用。没有处理器的
命令由 transport 返回 UNSUPPORTED；宿主也拒绝尚未实现的 clip/quality/file_indices
参数，避免用户选段后实际上创建整文件下载。完整功能目标继续按 parity-manifest 验收。
媒体实现方向为纯 Rust 索引/转封装；旧外部 FFmpeg 库只是未接入产品的本地实验，不算此目标完成。
